# 群管

「群管」是给 **QQBot 适配器**补上禁言能力的模块，插件名写死为「魔族陌:官机群管」，描述是「给QQBot适配器添加群管功能」。源码在 `apps/groupAdmin/groupAdmin.js`，具体请求由 `model/groupAdmin/` 与 `model/QQBot/interface.js` 完成。

QQBot 适配器本身不提供 `set_group_ban` 这类 OneBot 接口，所以这里直接走 QQ 开放平台的 `restrict_chat_setting` 接口——这也意味着**它只在 QQBot 适配器下可用**。

::: warning 默认是关闭的
`config/groupAdmin/default/setting.yaml` 里 `enable: false`。不打开的话三条指令全部静默返回，什么都不发生。而且这一组**没有锅巴面板**，只能手改 YAML，详见 [配置文件说明](/config/files)。
:::

## 启用条件

三条缺一不可，任一不满足都没有任何回复（静默返回）：

| 条件 | 说明 |
| --- | --- |
| QQBot 适配器 | `['QQBot'].includes(e?.bot?.adapter?.name)`，其它适配器直接 `return false` |
| `groupAdmin.setting.enable` | 群管总开关，默认 `false` |
| 仅群聊 | `this.e.group` 为空（私聊）时返回 |

过了这三关之后还有权限校验，失败时**会回复**而不是静默：

| 校验 | 要求 |
| --- | --- |
| 机器人权限 | 机器人必须是群管理或群主（`e.group.is_admin`），否则提示「Bot权限不足，需要管理员权限」 |
| 操作者权限 | 操作者必须是**群主、群管理或主人**，否则提示「该命令仅限群管理员可用」 |

主人（`e.isMaster`）可以跳过「操作者权限」这一关，但**跳不过「机器人权限」**——机器人自己不是管理，主人也禁言不了。

失败时的回复格式固定：

```text
***
**操作失败**
>造成的原因如下：
>- 该命令仅限群管理员可用
***
```

## 指令一览

| 指令 | 正则 | 说明 |
| --- | --- | --- |
| `#禁言` | `^#禁言\s?(([A-Z0-9]+)\s)?(数字)?(时间单位)?` | 禁言被 @ 的成员，可一次 @ 多人 |
| `#解禁` | `^#解禁` | 解除被 @ 成员的禁言，会显示每人剩余禁言时间 |
| `#解除全部禁言` | `^#解除全部禁言$` | 解除本群所有人的禁言 |

注意 `#禁言` 与 `#解禁` 的正则**没有结尾锚点**，后面跟其他文字也能触发；`#解除全部禁言` 则要求完全匹配。三条指令都**必须带 `#`**，不带前缀发「禁言」不会响应。

## 禁言语法

```
#禁言 @张三
#禁言 @张三 10
#禁言 @张三 10 秒
#禁言 @张三 半小时
#禁言 @张三 @李四 30 分钟
```

拆开看是「**@ 谁**」+「**多少**」+「**什么单位**」三段，后两段都可省略。

### 禁言对象只能靠 @

对象**只从 @ 提及里取**：源码先读 `e.mentions`，为空时再从原始消息里抠 `<@...>` 形式的 openid。所以：

- 只 @ 一个人 → 禁言一个人；@ 多个人 → 一起禁言。
- **直接打 openid 或 QQ 号是没用的**，不会被识别成目标。
- 禁言时会过滤掉 `member_role` 不是 `member` 的人（群主、管理员不会被禁）以及机器人账号；过滤后列表为空就回「未找到可禁言对象」。
- `#解禁` 同样按 @ 取人，但只过滤非 `member` 的角色，不再额外排除机器人。

### 数字支持中文

「多少」这一段由 `tools/translateChinaNum.js` 解析，阿拉伯数字和中文数字都认：

| 写法 | 解析结果 |
| --- | --- |
| `10` | 10 |
| `十` | 10 |
| `三十` | 30 |
| `一百二十` | 120 |
| `两` | 2 |

这个工具支持 `零一二两三四五六七八九` 与 `十百千万亿`，源码取自 [yenai-plugin](https://gitee.com/yeyang52/yenai-plugin)（GPL-3.0，未做修改），见 [鸣谢](/other/thanks)。

不写数字时按 `1` 处理。

### 时间单位

单位同样可选，缺省按 **60 秒**算。可用的写法：

| 单位 | 秒数 | 可写的词 |
| --- | --- | --- |
| 毫秒 | 0.001 | `毫秒` |
| 秒 | 1 | `秒`、`s`、`second` |
| 分 | 60 | `分`、`分钟`、`m`、`min`、`minute` |
| 时 | 3600 | `时`、`小时`、`h`、`hour` |
| 天 | 86400 | `天`、`日`、`d`、`day` |
| 周 | 604800 | `周`、`w`、`week` |
| 月 | 2592000 | `月`、`month` |
| 年 | 31536000 | `年`、`y`、`year` |

英文单位不区分大小写（源码会先 `toUpperCase()` 再查表）。所以：

| 输入 | 实际禁言时长 |
| --- | --- |
| `#禁言 @张三` | 1 × 60 = **60 秒**（回复里显示「1分钟」） |
| `#禁言 @张三 10` | 10 × 60 = **600 秒** |
| `#禁言 @张三 10 秒` | **10 秒** |
| `#禁言 @张三 半小时` | 0.5 小时 → `parseInt` 后是 **1800 秒** |
| `#禁言 @张三 五分钟` | **300 秒** |

::: tip 单位是从整条消息里「找第一个」
源码用 `e.msg.match(/毫秒|秒|S|...|YEAR/)` 取第一个命中的单位，数字则是取第一个命中 `[零一壹二两三四五六七八九十百千万亿\d]+` 的片段。这条规则有两个副作用：

1. 单位词出现在别处也会被当真——比如被 @ 的人昵称里带「天」「分」，可能把单位认错。
2. 一句话里同时出现多个数字时，只认第一个。

想稳一点就把「@ 谁 + 数字 + 单位」写得干净些，别在指令里夹带别的数字。
:::

## 解禁

```
#解禁 @张三
#解除全部禁言
```

- `#解禁` 会先拉一次群禁言列表（`restrict_chat_setting` 的 GET），把被 @ 的人与列表比对，然后**逐人显示剩余禁言时间**，形如「禁言时间剩余：1 小时 20 分钟 3 秒」。
- `#解除全部禁言` 把列表里的人一次性全部解禁，同样列出每人的剩余时间；列表为空时**什么也不回**。
- 两者都是把 `time` 置 `0`，对应请求体里的 `op: 'del'`。
- 剩余时间是通过 `mute_expire_at` 与当前时间相减算出来的，会按天 / 小时 / 分钟 / 秒拼接，不足一秒显示「0 秒」。

## 底层接口

| 方法 | 请求 | 用途 |
| --- | --- | --- |
| `getGroupMuteInfo()` | `GET /v2/groups/{id}/restrict_chat_setting` | 取群禁言列表 |
| `muteMember(openid, time, obj)` | `POST /v2/groups/{id}/restrict_chat_setting` | 禁言 / 解禁，`time` 为 0 时是解禁 |

`muteMember()` 每 20 人一批发送（`for (let i = 0; i < all.length; i += 20)`），`mute_expire_at` 由「当前秒 + 时长 + 1 秒」按 `+08:00` 生成。也就是说**实际禁言会比填的时长多出约 1 秒**。详见 [QQBot 接口](/feature/qqbot-api)。

## 配置项

配置文件是 `config/groupAdmin/config/setting.yaml`（仓库自带模板 `config/groupAdmin/default/setting.yaml`）。

| 配置键 | 默认值 | 说明 |
| --- | --- | --- |
| `groupAdmin.setting.enable` | `false` | 群管总开关 |
| `groupAdmin.setting.priority` | `100` | 指令优先级，数字越小越先响应（**改后需重启**） |

::: warning 只能手改
锅巴面板的 schema 里没有 `groupAdmin` 这一组，面板上看不到这两项。改 `enable` 保存即生效，改 `priority` 要重启机器人（它在插件构造时就读取了）。
:::

## 常见问题

### 发 `#禁言 @某人` 没反应

按顺序查：

1. `enable` 是不是还是默认的 `false`。
2. 当前适配器是不是 QQBot。
3. 机器人自己有没有群管理权限——**这条最容易被忽略**，而且失败时会回复「Bot权限不足」，如果连这条回复都没有，说明卡在前两步了。
4. 发指令的人是不是群主 / 群管理 / 主人。

### 为什么群主和管理员禁不了

`muteMember` 会先把 @ 列表过滤成 `member_role === 'member'` 的人，群主和管理员会被直接剔除。这是接口层的限制，不是插件故意为之。

### 禁言时长对不上

多半是单位默认值：**不写单位时按 60 秒算**，所以 `#禁言 @张三 10` 是 10 分钟而不是 10 秒。另外实际到期时间会多加约 1 秒（见上文「底层接口」）。

### 解除全部禁言没回消息

群禁言列表本来就是空的，源码在这种情况下不会回复任何内容。
