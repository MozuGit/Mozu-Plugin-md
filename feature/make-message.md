# 伪造聊天

「伪造聊天」可以把一段自定义文本伪装成指定 QQ 号发出的群聊记录，以合并转发的形式发到当前群。常用于整活、公告式吐槽和复读玩梗。

::: warning 使用前注意
伪造内容由使用者自己负责，请勿用来伪造他人发言进行攻击或误导。非主人发送的伪造消息会在 60 秒后被撤回。
:::

## 启用条件

| 条件 | 说明 |
| --- | --- |
| 仅群聊 | 私聊发送会直接回复「私聊暂不支持此操作」 |
| 非 QQBot 适配器 | 源码在 QQBot 适配器下直接返回 `false`，即该功能只在其它适配器（如 OneBotv11）生效 |
| `example.makeMessage.enable` | 伪造聊天开关，默认 `true` |
| `example.makeMessage.onlyMaster` | 仅主人使用，默认 `false`；打开后只有主人能触发 |

插件名为「魔族陌:伪造聊天」，优先级 `priority: 1145`（源码写死，锅巴面板不提供该项）。

## 指令一览

| 指令 | 说明 | 备注 |
| --- | --- | --- |
| `#伪造聊天` | 伪造一段或多段聊天记录 | 正则 `^#?伪(造|装)聊天`，`#伪装聊天`、不带 `#` 的写法都可以 |
| `#伪造复读 <内容> [次数]` | 随机抽取群成员复读同一句话 | 正则 `^#?伪(造|装)复读\s*(.+?)(?:\s+(\d+))?$` |

## 语法详解

README 给出的示例是：

```
#伪造聊天123456789,伪造消息内容,2026-1-1|114514,伪造消息内容
```

拆开看，这里有三层结构：`|` 分隔多条消息，`,` 分隔同一条消息里的各个字段，字段依次是**被伪造的 QQ 号、消息内容、时间**。

### 被伪造的 QQ 号（第 1 个字段）

```text
#伪造聊天123456789,伪造消息内容
```

- 必须是纯数字，源码会做 `Number()` 转换后用它去查昵称。
- 昵称由 `Bot.pickUser(QQ号).getInfo()` 实时获取，所以这个 QQ 号需要是机器人能查到的用户；查不到时会报错，建议填群成员或好友的 QQ 号。
- 号码和内容之间的逗号后面可以带空格，源码用 `/,\s*/` 切分，`,` 与 `, ` 都能识别。

### 消息内容（第 2 个字段）

就是那条伪造消息的正文，可以包含空格、中文、表情等。注意两点：

- **正文里不能出现英文逗号 `,`**：它会被当成字段分隔符，多余的部分会被忽略。
- 正文里可以用 `=img=` 占位符插入图片，详见下文。

### 时间（第 3 个字段，可选）

```text
#伪造聊天123456789,昨天的消息,2026-1-1
```

- 必须能被 `new Date()` 解析，比如 `2026-1-1`、`2026/1/1 12:00`。
- 解析失败或该字段为空时，时间会回退成消息发送的当前时间。
- 省略该字段（只写两个字段）时同样使用当前时间。

### 多条消息

用 `|` 分隔每一条消息，每条消息内部再按 `,` 分成 2 ~ 3 个字段，字段规则与单条完全相同：

```text
#伪造聊天123456789,第一条内容,2026-1-1|114514,第二条内容|114514,第三条内容,2026-1-2
```

时间字段可以只在部分消息里出现，其余消息使用当前时间。

### 图片占位 `=img=`

消息正文里的每个 `=img=` 会被移除，并依次替换为你在这条指令里附带的图片（源码从最后一张开始取，只剩一张时会重复使用）。例如附带 1 张图再发送：

```text
#伪造聊天123456789,快看这个 =img=
```

附带图片的数量决定最多能插入几张，`=img=` 多余时不会继续插入。

::: details 只写一个字段时的兜底行为
如果某一段消息里没有逗号（只有一个字段），源码会走兜底分支：指令里带了艾特就用被艾特的人当作者，否则用发送者自己的 QQ 号当作者，正文则取整条指令的剩余文本。这一段属于边缘情况，正常使用请老老实实写 `QQ号,内容`。
:::

## 伪造复读

```text
#伪造复读测试 10
#伪装复读 早上好 5
```

- 内容与次数用空格分隔，**次数是最后一段纯数字且可省略**；省略时使用 `example.makeMessage.repeatCount`（默认 `10`，源码里还有 `|| 10` 兜底）。
- 源码会取当前群的成员列表，**先剔除 `whiteQQList` 里的成员**，再从中随机、不重复地抽取成员来「发言」，所以实际条数受剩余成员数量限制：成员抽完就停止；剩余成员为 0 时整条指令静默返回。
- 所有伪造消息的时间都是发送时刻，撤回规则与伪造聊天一致。

## 配置项

配置文件是 `config/example/config/makeMessage.yaml`（仓库自带的模板为 `config/example/default/makeMessage.yaml`）。

| 配置键 | 锅巴面板标签 | 说明 | 默认值 |
| --- | --- | --- | --- |
| `example.makeMessage.enable` | 伪造聊天开关 | 总开关 | `true` |
| `example.makeMessage.onlyMaster` | 仅主人使用 | 打开后只有主人能使用伪造聊天与伪造复读 | `false` |
| `example.makeMessage.whiteQQList` | 白名单QQ | 「防止白名单QQ被伪造」，面板上使用好友选择器。两处生效：伪造聊天里名单内的 QQ 被伪造时，非主人的请求会跳过该条（主人不受限制）；伪造复读时会**先把名单里的成员从随机池里剔除**，池子被剔空时整条指令直接返回 | `[]` |
| `example.makeMessage.repeatCount` | 默认复读次数 | 伪造复读未填次数时的默认值，面板限制最小为 `0` | `10` |

## 限制与注意事项

- 私聊不支持，QQBot 适配器下不生效。
- 非主人发送的合并转发设置了 `recallMsg: 60`（60 秒后撤回）；主人发送的是 `recallMsg: 0`（不主动撤回）。
- 伪造聊天的消息条数在源码中没有上限，只受字段解析规则限制；伪造复读的条数上限为群成员数量。
- 白名单只对非主人生效：伪造聊天里的判断是「白名单命中且不是主人 → 跳过这一条」；伪造复读则是无条件把名单成员排除出随机池。
- 被伪造的 QQ 号必须能被机器人查到昵称，否则整条指令会失败。
