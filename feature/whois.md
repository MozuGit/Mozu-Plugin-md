# 天选之人

一条指令的群聊小游戏：发 `天选之人`，机器人从群里随机抽一个人**当场禁言几秒**。源码是 `apps/example/whois.js`。

::: warning 会真的禁言
抽中的人会被禁言 5～60 秒。只在你自己的群里用。
:::

## 使用条件

| 条件 | 说明 |
| --- | --- |
| 指令 | `天选之人` / `#天选之人`（`^#?天选之人$`） |
| 适配器 | 仅 QQBot，其他适配器静默返回 |
| 场景 | 仅群聊 |
| 开关 | `example.whois.enable`，默认**开启** |
| 机器人权限 | 必须是群管理，否则不响应 |

## 流程

1. 从群成员里随机抽一人。
2. 若 `self_add_rate` 开启、随机数大于 70、且发送者不是主人 → 把目标换成**发送者自己**（约三成概率）。
3. 随机一个 5～60 秒的时长。
4. 若 Redis 里记着上一轮的倒霉蛋（`Mozu:whois:mute:<群号>`），先给他解禁。
5. 禁言目标并记进同一个键（TTL 等于禁言时长），然后回复一条带「我也要玩喵~」按钮的 Markdown。

每群同时只记录一个人，所以不会出现两个人一直被禁。

## 配置

| 字段 | 面板名称 | 默认 | 说明 |
| --- | --- | --- | --- |
| `example.whois.enable` | 天选之人开关 | `true` | 总开关 |
| `example.whois.self_add_rate` | 发起人概率 | `true` | 开启后发送者自己中招的概率约三成，主人不受影响 |

::: tip `self_add_rate` 不是加权
它是在随机结果之外**再做一次判定**：命中就直接把目标换成发送者，原结果作废，并不会提高其他人被抽中的概率。
:::

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 没反应 | 不是 QQBot、`enable` 被关、或在私聊 |
| 机器人不回应 | 机器人不是群管理（这种情况不报错） |
| 改不了时长 | 时长在源码中固定为 5～60 秒随机，没有配置项 |
