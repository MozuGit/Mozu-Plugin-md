# 魔族陌修仙

「魔族陌修仙」是 Mozu-Plugin 的核心玩法模块：在群里修炼、突破境界、猎杀妖兽、探索秘境、创建宗门、冲榜拿称号，并用兑换码发放奖励。玩家数据全部存在 Redis 里，开关与数值都能在锅巴面板中调整，参见 [锅巴面板配置](/config/guoba)。

::: warning 修仙仍在开发中
指令、数值与配置项都可能随版本变化，本文内容以当前源码为准；如果机器人的实际回复与本文不符，请以源码和实际回复为准。
:::

::: tip 常用指令
`修炼`、`开采`、`修仙签到`、`突破`、`开始闭关`、`猎杀妖兽`、`探索秘境`、`我的宗门`。想一次看全，直接发送 `#修仙帮助`。
:::

## 启用条件

### 仅 QQBot 适配器生效

修仙模块的所有入口（`apps/xiuxian/xiuxian.js`、`apps/xiuxian/help.js`）都会先做同一个判断：

```js
if (!['QQBot'].includes(e?.bot?.adapter?.name) || !Config.xiuxian.setting.enable) return false
```

也就是说，**只有 QQBot 适配器下的消息才会触发修仙指令**。其它适配器下发送修仙指令不会有任何反应（静默返回，不报错、不回复）。这是因为修仙的输出使用了 QQBot 专属的 Markdown 与按钮能力。

### 修仙总开关

`config/xiuxian/setting.yaml` 中的 `enable` 是修仙总开关（默认 `true`）。关闭后所有修仙指令与定时任务（备份、称号发放、称号清理）都不再执行。

### 群黑名单 / 白名单

`group` 这个配置项用三个取值控制名单模式：

| 取值 | 含义 | 行为 |
| --- | --- | --- |
| `0` | 不启用 | 所有群都能触发修仙指令（默认值） |
| `1` | 黑名单 | `blackGroup` 里的群不触发任何修仙指令 |
| `2` | 白名单 | 只有 `whiteGroup` 里的群能触发修仙指令 |

判定发生在指令触发阶段，命中黑名单或不在白名单时直接 `return false`，不会给出任何提示。

::: tip 填名单时注意群号格式
源码比较的是 `e.group_id` 原值（未做去前缀处理）。QQBot 适配器下群号通常带 `self_id:` 前缀，建议直接使用锅巴面板的群选择器（`GSelectGroup`）来填写，避免手填格式不一致导致名单失效。
:::

### 指令前缀与 forceSharp

`forceSharp`（锅巴面板里叫「强制用#触发」，默认 `false`）控制修仙指令是否需要前缀，它会同时影响两处：

| forceSharp | 触发要求（`model/xiuxian/RegExp.js`） | 帮助与按钮前缀（`model/xiuxian/help.js`、`lib/protocol.js`） |
| --- | --- | --- |
| `false` | `^#?`，`修炼` 与 `#修炼` 都能触发 | 无前缀 |
| `true` | `^#`，必须以 `#` 开头 | `/`（写成 `/修炼`） |

::: info 为什么帮助里显示的是 `/`
指令正则匹配的是 `#`，帮助列表与按钮文本里拼的却是 `/`，这两者并不冲突：**云崽会把以 `/` 开头的消息自动转换成 `#` 开头**，所以 `/修炼` 与 `#修炼` 都能触发。锅巴面板对该项的说明也因此写成「前缀必须有#或/才能触发指令」。
:::

### 优先级 priority

`priority` 默认 `1000`，修仙指令与 `#修仙帮助` 共用它。数字越小优先级越高，锅巴面板标注「修改后需要重启才能生效」。如果其它插件也监听了同样的关键字，可以调小这个值让修仙先响应。

## 帮助指令

帮助指令的正则是 `#?(魔族陌)?修仙帮助$`，因此下面几种写法都能触发：

- `修仙帮助`
- `#修仙帮助`
- `魔族陌修仙帮助`
- `#魔族陌修仙帮助`

::: warning 后面不能再跟别的内容
锚点补上之后，`修仙帮助我` 这类「帮助 + 其他文字」的写法**不再触发**（旧版本会因为它没有锚点而被匹配到）。想要别的功能请单独发指令。
:::

帮助内容分为四类：**🎉基础指令**、**🎄宗门指令**、**⭐️排行指令**、**🌈兑换指令**，每条指令都会被渲染成可点击的行内指令（点击即发送），四类标题都用 `>**…**` 的引用样式排版；第一行是固定的「联系主人」入口，跳转 QQ `3343712589`（不再读 `setting.contact`）。指令按显示宽度排版，一行放得下（累计不足 12 个字符）就并排，放不下就换行。

## 玩法机制

### 数值系统

每个玩家在初始化的那一刻会在 Redis 里建立档案，核心字段与来源如下：

| 数值 | 含义 | 主要来源 |
| --- | --- | --- |
| 修为 `cult` | 突破境界的门槛，也是战力的主要因子 | 修炼、签到、丹药、切磋、闭关收益、妖兽奖励、兑换码 |
| 灵石 `ls` | 通用货币 | 开采、签到、妖兽奖励、出售丹药/功法、兑换码 |
| 境界 `realm` | 在境界表中的下标，越高越强 | 突破 |
| 战力 `power` | 按 `powerFormula` 计算（默认 `realm / 10 * cult / 100`），再叠加灵根与功法的百分比加成 | 自动计算 |
| 灵根 / 功法 | 提供百分比 `addition` 加成 | 灵根抽取、秘境掉落 |

玩家数据存放在 `Mozu:xiuxian:playerInfo:<id>`、背包在 `Mozu:xiuxian:playerBag:<id>`、宗门在 `Mozu:xiuxian:sectInfo:<id>`，OpenID 与数字 ID 的映射在 `Mozu:xiuxian:openid:forward` / `:reverse` / `:counter`。字段级说明见 [修仙数据扩展](/develop/xiuxian-data)。

### 修炼、开采与签到

- `修炼`：单次随机获得 `mincult` ~ `maxcult`（默认 1000 ~ 3000）修为，冷却 `xiulian` 默认 300 秒。
- `开采`：单次随机获得 `minls` ~ `maxls`（默认 1000 ~ 3000）灵石，冷却 `kaicai` 默认 300 秒。
- `修仙签到`：每天一次，按 `sign` 配置发放（默认 18888 修为 + 18888 灵石），同时累计签到次数，签到榜就是按它排名的。

### 突破与境界

境界表在 `config/xiuxian/default/Realm.yaml` 的 `Realms` 中，每一项包含 `name`（境界名）、`value`（突破所需修为）、`success`（突破成功率 %）、`failed`（失败扣除的修为）。`突破` 的流程是：修为达到当前境界的 `value` → 按 `success` 掷点数 → 成功则境界 +1，失败则扣掉 `failed` 修为。境界表走完即为「世界极限」，无法再突破。

### 闭关

`开始闭关` 后玩家进入闭关状态，此时所有操作都会提示「闭关中」，同时会被移出随机切磋匹配池。收益按每小时 `retreat.cult`（默认 5000 修为）累计，`retreat.max`（默认 24 小时）是收益上限——超时后时间仍会累计，但收益不再增加。结束闭关走 `结束闭关` → 确认，结算时才把修为写回档案。

### 切磋

| 项目 | 规则 |
| --- | --- |
| 门槛 | 双方修为都需 ≥ 5000，任一方闭关中则无法切磋 |
| 冷却 | 发起方 `pvp.atk_cd` 默认 60 秒；被切磋方 `pvp.def_cd` 默认 120 秒 |
| 胜率 | 己方战力 ÷ 双方战力之和，再乘 0.95 ~ 1.05 的随机系数，最终限制在 1% ~ 99% |
| 结算 | 胜方加、负方减 1000 ~ 5000 修为 |

`随机切磋` 使用匹配池 `Mozu:xiuxian:random:pvp`：修为 > 5000 的玩家会被写入这个池子（低于门槛或开始闭关会被移出），再从池中按战力找到与你相近的对手，并在附近做小范围随机。

::: tip 双方冷却各记各的
玩家档案里现在用**两个独立字段**记冷却：`切磋冷却` 记自己发起的时间（对应 `pvp.atk_cd`），`被切磋冷却` 记被别人打的时间（对应 `pvp.def_cd`）。1.3.0 修正了被动方校验读错字段的问题，此前 `def_cd` 实际上没有被正确执行。
:::

### 妖兽猎杀

妖兽配置在 `beast.yaml`，每只都有 `power`（战力）、`reward`（成功奖励的修为与灵石）、`punishment`（失败扣除的修为）。`猎杀妖兽 <妖兽ID>` 的胜率算法与切磋相同，冷却 `huntBeastCD` 默认 600 秒。可以先 `妖兽列表` / `查看妖兽 <ID>` 对比战力再出手。

::: tip 失败不会把修为扣成负数
1.3.0 起失败结算写成 `cult = Math.max(0, cult - punishment.cult)`：修为不足时最低扣到 0，不会出现负修为。旧版本会照扣，可能把修为扣成负数。
:::

### 秘境探索

秘境配置在 `drop.yaml`：`secretRealms` 定义名称、难度 `level`（`easy` / `medium` / `hard`）、门票 `cost_ls`、掉落率 `drop_rate`；`secretRealm_limit` 定义三档难度各自的最低境界（默认 `easy: 1`、`medium: 45`、`hard: 81`）。

`探索秘境 <秘境ID>` 会先扣灵石、做境界校验，然后按 `drop_rate` 判定掉落，掉到的东西里约 70% 是丹药、30% 是功法，直接进背包。每次消耗门票灵石，所以 `探索秘境十次 <ID>` 与 `探索秘境百次 <ID>` 会按次数成倍扣费。

### 背包、丹药与功法

- 背包分页展示，每页 5 条：`丹药背包 <页码>`、`功法背包 <页码>`，条目上会显示编号与可用的操作按钮。
- `使用丹药 <编号> 数量:1` 直接转化为修为；`一键使用丹药` 清空全部丹药并一次性结算。`出售丹药 <编号> 数量:1` 换成灵石。
- `学习功法 <编号>` 按该功法的 `rate`（默认 50%）判定，失败会按 `deduct_cult` 反噬修为，成功后功法的 `addition` 才计入战力加成；`一键学习功法` 会批量处理。编号现在会被正则正确捕获（`/^#?(?:一键)?学习功法\s*(\d*)/`），1.3.0 之前这里取不到编号，按编号学习会失败。

### 灵根

灵根配置在 `sroot.yaml`，分四个档位：五行灵根、高级灵根、极品灵根、至臻灵根，各自的掉落概率在 `root_drop`（默认 79 / 15 / 5 / 1），每条灵根有自己的 `addition` 加成百分比。

- `获取灵根`：花 `obtain_sroot_ls`（默认 100000 灵石），只在没有灵根时可用，且只会得到五行灵根之一。
- `洗灵根`：花 `wash_sroot_ls`（默认 50000 灵石）洗一次，按概率产出候选灵根；`洗灵根十次` 一次洗十组。
- `替换灵根 <序号>`：从候选里确认替换；`取消替换灵根`：放弃本次候选。

### 宗门

- `创建宗门` 需要 `create_sect_ls`（默认 200000 灵石），创建者自动成为宗主，宗门默认名为「修仙宗门」。
- 宗门等级表 `sect_level` 共 10 级，每级定义升级所需经验 `up_exp`、成员上限 `memberMax`（10 → 100）与签到奖励。`宗门升级` 需要成员权限 ≥ 7（长老及以上）。
- `宗门签到` 每天一次，按当前宗门等级发放修为、灵石与宗门经验；`宗门供奉 <灵石>` 需为 10 的倍数，每 10 灵石换 1 点宗门经验，同时累计个人贡献。
- 成员权限从 1 到 10 对应新人、成员、精英、资深、执事、未命名、长老、大长老、副宗主、宗主；审核与升级类操作都要求长老及以上。
- 入宗审核模式由 `sect_validation.audit.mode` 决定：`0` 手动审核、`1` AI 审核、`2` 关键词审核、`3` 无需审核。AI 审核使用 OpenAI 配置，参见 [OpenAI 配置](/config/openai)；名称与简介还有字符数上下限与换行开关。

### 称号

称号由定时任务发放：`title.rankTitle.cron` 默认 `0 0 0 ? * 1`（每周执行一次），按修为、灵石、战力、闭关四个榜单的前若干名依次发放对应称号，有效期 `validDays` 默认 7 天（`0` 表示永久）。过期称号由清理任务 `title.cleanTitle.cron`（默认 `0 0 0 * * *`，每天 0 点）移除。用 `我的称号` 查看，用 `设置称号 <称号ID>` 佩戴。

### 兑换码

- `生成兑换码` 是主人指令，支持附加参数：`数量:5`（生成数量）、`文本:XXX`（自定义码，多个文本会生成多个码）、`修为:1000`、`灵石:1000`（可写多段，结算时累加）、`强制设置`（把修为/灵石直接设为给定值而不是累加）、`通用`（通用码，每人可用一次；不写则是普通码，全服只能用一次）。不指定文本时随机生成 16 位大写字母与数字的组合。
- `使用兑换码 <兑换码>`：普通码只能被使用一次，通用码每个用户限一次。
- `删除兑换码 <兑换码>` 支持一行一个批量删除，`删除全部兑换码` 清空全部。

## 兑换指令

| 指令 | 说明 | 备注 |
| --- | --- | --- |
| `使用兑换码` | 使用兑换码领取修为与灵石 | `使用兑换码 <兑换码>`；普通码全服一次，通用码每人一次 |
| `生成兑换码` | 生成兑换码并发给使用者 | 主人专用；支持 `数量:`、`文本:`、`修为:`、`灵石:`、`强制设置`、`通用` |
| `删除兑换码` | 删除指定兑换码或全部兑换码 | 主人专用；`删除全部兑换码` 清空全部 |

::: details 兑换码参数示例
```
#生成通用兑换码 数量:3 修为:10000 灵石:10000
#生成兑换码 文本:MOZU2026 修为:5000
#使用兑换码 MOZU2026
#删除兑换码 MOZU2026
```
`通用` 表示这张码可以被多个用户各用一次；加 `强制设置` 时修为与灵石会被直接设为给定数值，而不是累加。
:::
