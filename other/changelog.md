## 当前版本

**v1.3.0**

这个值来自仓库根目录 `package.json` 的 `version` 字段。`model/Config/Version.js` 读取它并暴露为 `Version.Plugin_Version`，启动日志、管理台「关于」页用的都是同一个值——所以升级后只要 `package.json` 变了，版本号就会跟着变。

## 1.3.0 的主要变化

版本号仍是 `1.3.0`，但发布后又合入了一批修复，重心在内置管理台的安全性上。

### 管理台（影响最大）

| 变化 | 说明 |
| --- | --- |
| 登录态改为 7 天过期 | token 从「Redis 集合 `Mozu:panel:token`、没有 TTL」改成独立键 `Mozu:panel:token:<token>`（写入时带 `EX`，`TOKEN_TTL` 为 7 天）。**插件启动时会 `DEL` 掉旧的集合键，所以升级后所有浏览器都要重新登录** |
| 登录限流按 IP 记账 | 密码错误计数键由全局的 `Mozu:panel:password:error` 改为 `Mozu:panel:password:error:<IP>`，验证码尝试次数记在 `Mozu:panel:code:<IP>:count`。刷某一个 IP 不会再连累其他访客 |
| 新增 `trustProxy` | `config/panel/default/login.yaml` 新增 `trustProxy`（默认 `false`）。客户端 IP 改由 Express 的 `req.ip` 决定，不再无条件信任 `x-forwarded-for`。**挂了 nginx / CDN 的必须按实际层数设为 `1` 或 `2`**，否则限流会把所有访客当成同一个 IP。默认值不会替你判断，请手动确认；只有把它删空或填成识别不了的值时，插件才会在启动、以及首次遇到反代请求时各警告一次 |
| 重置密码需要动态码 | 启用两步验证后，「忘记密码」流程除短信式验证码外还要填 TOTP 动态码，缺码时前端会展开输入框 |
| 密钥不再回显 | 锅巴面板不再把 `totp.secret` 发到前端，面版密码输入框换成 `InputPassword`；修仙配置的校验提前到**写文件之前**，校验失败不会留下写了一半的配置 |
| 其它加固 | 验证码由「实际只有 7 位」修正为真正的 8 位；密码比对改用 `crypto.timingSafeEqual`；退出登录无论 token 是否有效都返回成功；`lib/Redis.js` 的连接错误会打日志而不是静默吞掉 |

### 修仙

- `修仙帮助` 的正则补上结尾锚点（`#?(魔族陌)?修仙帮助$`），`修仙帮助xxx` 这类写法**不再触发**。
- 帮助页的「联系主人」改成固定跳转 QQ `3343712589`，`setting.contact.peerUid` / `peerName` 变成只写不读的遗留配置。
- `猎杀妖兽` 失败不再把修为扣成负数（最低扣到 0）。
- 修正被切磋方冷却读错字段（`pvp.def_cd` 此前实际未生效）、`学习功法 <编号>` 取不到编号必然失败、排行榜取数错位、出售丹药写入错误数组、宗门成员权限字段名等问题。

### 其它

- **备份文件名的时间戳格式由 `2026-01-01_08:00` 变成 `2026-01-01_08-00`**（冒号在 Windows 文件名里非法）。自定义文件名会经过 `safeBackupName()` 清洗，`scripts/backup.js` 也会自动创建备份目录。有依赖旧命名格式的脚本需要同步改。
- 定时点赞的「点赞目标」选择器由群选择器换成好友选择器（`GSelectFriend`）。
- 伪造复读现在会先把 `whiteQQList` 里的成员从随机池里剔除，池子被剔空时指令直接返回。
- `package.json` 新增 `"engines": { "node": ">=21" }`。

::: tip 这次升级最需要注意的两件事
1. **升级后管理台要重新登录**（旧 token 会被清掉）。
2. **挂了反向代理就一定要配 `trustProxy`**，否则登录限流会按代理 IP 记账、形同虚设。做法见 [部署与安全](/webui/security)。
:::

## 如何查看自己正在运行的版本

| 方式 | 说明 |
| --- | --- |
| 看启动日志 | Yunzai 启动时会打印 `┃ Mozu-Plugin 载入成功` 与 `┃ 版本：v…`（由 `index.js` 输出），这是最直接的方式 |
| 看本地文件 | 打开 `plugins/Mozu-Plugin/package.json`，查看 `version` 字段 |
| 管理台 | 登录内置管理台，进入「关于」页，会显示当前版本并与远端 `package.json` 比对，标注为最新版 / 可更新 / 测试版 |
| 修仙兜底文案 | 在修仙里发送尚未实现的指令时，兜底回复会带一行 `>版本：v…` |

::: tip 别只看「能跑」
排查问题时请把版本号一起贴上。不同版本的 `apps/` 与 `config/` 结构有差异，版本对不上时文档里的路径可能与你本地并不一致。
:::

## 版本号怎么读

版本号遵循 `主版本.次版本.修订号`，当前 `1.3.0` 是正式版本号：

- 数字部分变化代表功能与结构的实际变更，越大越新。
- 若版本号带 `-beta.N` 之类的后缀，说明是**预发布版本**：管理台「关于」页会据此把状态标成「测试版」，远端版本更高时标「可更新」，完全一致时标「最新版」。
- 想确认自己跑的是正式版还是测试版，看 `package.json` 的 `version` 有没有后缀即可。

## 升级前的准备

- 备份配置：复制一份 `config/` 目录（尤其是 `config/xiuxian/config/`，那里是修仙的实际数据）。
- 备份玩家数据：管理台「修仙备份」页或群内备份指令会把 `Mozu:xiuxian:*` 导出成 JSON，升级前跑一次更放心。
- 记下当前版本号，方便升级出问题时回退对比。
- 抄一份 `config/panel/config/login.yaml` 的 `host` / `port` / `password`，并记下是否启用了两步验证——升级后旧登录态会失效，配置不对就进不去管理台。

## 如何更新

插件内置了更新指令，需要**主人权限**（`apps/update.js` 里会检查 `e.isMaster`），实际动作交给 Yunzai 的更新模块执行：

| 指令 | 作用 |
| --- | --- |
| `#魔族陌更新` | 常规更新 |
| `#Mozu-Plugin更新` | 同上，用插件目录名调用 |
| `#魔族陌插件更新` | 同上 |
| `#魔族陌强制更新` | 强制更新，本地有改动时也覆盖 |
| `#更新Mozu-Plugin` | 反向写法，效果相同 |
| `#更新推送` | 拉取更新推送 |
| `#魔族陌更新日志` / `#Mozu-Plugin更新日志` | 直接在群里查看更新日志（读取框架的 `getLog`） |

也可以手动更新：进入插件目录执行 `git pull`，然后**重启 Yunzai** 让 `apps/` 重新扫描载入。

配置文件的处理规则要记住：`default/` 里**新增的键**会在读取时与你的用户配置合并（`getDefOrConfig()`，用户配置优先），而你已经改过的键不会被覆盖；`default/` 里新增的**整个文件**会在下次启动时被复制到 `config/`。所以升级后建议对照 [配置文件说明](/config/files) 检查有没有需要手动确认的新选项。

## 更新后的自检

1. 看启动日志：确认出现 `┃ Mozu-Plugin 载入成功` 与新的版本号，且没有 `载入插件错误：<文件路径>`。然后确认 `trustProxy` 与实际部署一致（挂了代理就改成 `1` 或 `2`）；如果日志里出现 `[魔族陌面版] 未配置 trustProxy` 的黄色警告，说明这一项被清空了，需要补上。
2. 重新登录管理台（旧 token 已被清理），进「关于」页：版本显示应与 `package.json` 一致，状态为「最新版」。
3. 打开锅巴面板：确认各功能 schema 正常加载（「魔族陌面版」分组里应能看到「反代/CDN 信任」），改一个开关保存后能写回 yaml。
4. 群里发一条 `#发言榜` 之类的轻量指令，确认消息链路正常；有 QQBot 适配器的话再发一条 `#修仙帮助`，确认帮助页与「联系主人」入口正常。

出问题时的排查思路见 [常见问题](/guide/faq) 与 [新增功能模块](/develop/module)。
